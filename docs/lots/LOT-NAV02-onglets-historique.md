# Fiche LOT-NAV02/03 — Navigateur : onglets et historique (Windows)

- Statut : Fait (bureau) ; Android inchangé (une page, grille d'onglets en phase mobile ; les commandes d'onglets y répondent « non disponible »)
- Exigences CDC : NAV-02 (onglets : création, fermeture, changement, restauration ; budget mémoire), NAV-03 (historique et favoris : local, recherche, effacement sans supprimer les médias)
- Maquette : `design/design_handoff_windows_v2` écran 8 — barre d'onglets 38 px (onglets 220 × 32, actif `surface`, pastille teal = médias détectés, ×, +), barre d'outils 48 px (précédent, suivant, recharger, accueil ; adresse en pilule 34 / rayon 17, police mono, cadenas teal, puce « N médias » ; étoile, favoris, historique), onglet interne `miarina://history`, bouton flottant en bas à droite (24 px)
- Inclus :
  - Onglets (Rust, `browser/desktop.rs`) : une vue web par onglet, au plus 12 onglets dont 4 avec une vue vivante ; au-delà, l'onglet d'arrière-plan utilisé le moins récemment est mis en veille (vue fermée, adresse et titre gardés) et se recharge quand on le sélectionne. Les pop-ups d'une page s'ouvrent dans un nouvel onglet. Fermer le dernier onglet laisse un onglet « Nouvel onglet ». Les onglets ouverts (adresse, titre, onglet sélectionné) sont enregistrés et restaurés au démarrage suivant ; seul l'onglet sélectionné se charge, les autres à la demande.
  - Détection par onglet : chaque onglet garde ses médias détectés (pastille sur l'onglet) ; le bouton flottant et la feuille de formats suivent l'onglet sélectionné.
  - Historique (migration SQLite v9, table `browser_history`) : chaque page affichée est notée (http(s) seulement), son titre est ajouté à son arrivée ; revenir sur la même page dans les 30 minutes met à jour la visite au lieu d'en ajouter une ; 10 000 visites au plus (les plus anciennes partent). Commandes `browser_history` (recherche titre ou adresse, `%` et `_` pris à la lettre), `browser_history_delete`, `browser_history_clear` (+ permissions).
  - Interface Windows v2 (`DesktopBrowser.tsx`, `HistoryTab.tsx`) : barre d'onglets (clic du milieu pour fermer), barre d'outils, adresse modifiable (Ctrl L), puce médias qui ouvre la feuille, étoile ; onglet Historique / Favoris avec bascule, recherche, regroupement par jour, retrait d'une visite ou d'un favori, « Effacer l'historique » avec confirmation (les téléchargements, la bibliothèque et les favoris restent) ; page de démarrage inchangée. FR / EN.
  - Raccourcis, que le focus soit dans l'application ou dans la page : Ctrl T (nouvel onglet, adresse prête), Ctrl W (fermer), Ctrl Tab / Ctrl Maj Tab (onglet suivant / précédent), Ctrl H (historique), Ctrl L, F5, Ctrl Maj S.
  - Correction au passage : le plugin Tauri « opener » injectait dans toutes les vues, pages visitées comprises, un script qui annulait les clics sur les liens `target=_blank` (et Ctrl / Maj + clic) pour les envoyer au navigateur système, appel refusé par les permissions : ces liens ne faisaient rien. Le script est désactivé (`open_js_links_on_click(false)`) ; l'application n'a aucun lien qui en dépendait. Ces liens ouvrent maintenant un onglet ; avec 12 onglets ouverts, la page s'ouvre dans l'onglet d'origine plutôt que nulle part.
- Adaptations :
  - La maquette ne dessine pas le contenu de l'onglet `miarina://history` : construit avec les éléments de l'écran Historique (titre 24, bascule segmentée, groupes par jour, note).
  - Le bouton « favoris » ouvre ce même onglet sur la vue Favoris (les favoris restent aussi sur la page de démarrage).
  - Un onglet mis en veille perd son historique Précédent / Suivant (il se recharge sur sa dernière adresse).
  - Le bouton « applications » et la barre du bas de la présentation Android disparaissent sous Windows : la barre latérale de l'application est toujours là.
- Tests : `cargo test -p storage` (40, dont historique : regroupement, recherche, `%` littéral, titres nettoyés, URL trop longue, effacement ; migration v9), tests Rust du module (liste sauvegardée, instantané des onglets) ; `vitest` 32 fichiers, 170 tests (nouveau `src/test/desktop-browser.test.tsx` : ouvrir, nommer, changer, fermer, Ctrl T, limite de 12 avec message, historique par jour, recherche, retrait, effacement confirmé, favoris) ; clippy sans nouvel avertissement.
- Recette native Windows (build release isolé, pages locales) :
  - 6 onglets ouverts : seulement 4 vues web vivantes ; resélectionner un onglet en veille le recharge (titre, vidéo détectée : pastille 1) et met en veille le plus ancien ;
  - `window.open` (avec ou sans `noopener`, depuis un script ou un vrai clic) : nouvel onglet sélectionné ; lien `target=_blank` cliqué : nouvel onglet après la correction ci-dessus (avant : rien) ;
  - fermeture puis relance de l'application : 10 puis 12 onglets restaurés avec titres et onglet sélectionné, seule la page sélectionnée chargée ;
  - fermer des onglets libère leurs vues ;
  - historique réel : 19 visites notées, recherche « Page 3 » → 1 ; onglet Historique en français conforme (groupe Aujourd'hui, heure, titre, hôte).
- Non testé en recette : raccourcis clavier depuis la page (WebView2 ne reçoit pas les touches simulées par CDP ; couverts côté application par les tests), sites réels avec beaucoup d'onglets (mémoire non mesurée : à faire dans L00).
- Non inclus : navigation privée, synchronisation, import de favoris d'autres navigateurs, grille d'onglets Android, enregistrement de l'historique sur Android.
- Retour arrière : revert ; la table v9 et le réglage `browser.tabs` sont ignorés par l'ancien code.
